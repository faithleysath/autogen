Survey the repository before committing to a plan or implementation.
- Read the frozen contract and the closest implementation files first.
- Prefer existing tests, config files, and prior patterns over inventing new structure.
- Use git status and diff to understand the current workspace before concluding.
- For greenfield repositories, stop after a brief top-level survey once you confirm the app code does not exist yet.
- Ignore git internals, generated artifacts, and dependency folders unless the task explicitly targets them.
